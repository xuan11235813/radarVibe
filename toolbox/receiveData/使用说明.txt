receiveData 雷达单帧采集工具使用说明
====================================

1. 工具用途
监听雷达发往本机 UDP 1995 端口的数据，接收首个完整且通过 SYNC 校验的
8 MiB 原始帧，仅将 ch6、ch7 两个通道转换为 CSV 文件后自动退出。
每次运行只保存一帧；原始 UDP 帧仍完整接收，导出时只解码 ch6、ch7。

2. 运行准备
电脑与雷达应处于能够接收广播的同一局域网，雷达目标端口为 1995。
允许 Windows 防火墙接收该程序的 UDP 1995 流量，确保该端口未被其他程序占用。
已有 receiveData.exe 时不需要安装 Go；从源码构建需要 Go 1.25 或更新版本。
建议在终端运行，以便查看成功信息或错误原因。

3. 快速使用
在本目录（toolbox/receiveData）打开 Git Bash，执行：
  ./receiveData.exe

在本目录打开 PowerShell，执行：
  .\receiveData.exe

默认监听 0.0.0.0:1995，接收超时为 30 秒。成功时显示 Saved 和文件绝对路径。
输出文件默认名为 radar_年月日_时分秒.纳秒.csv，保存在启动程序时的当前工作目录，
不一定是 exe 所在目录。

持续等待，直到收到有效帧或按 Ctrl+C：
  ./receiveData.exe -timeout 0

指定输出文件：
  ./receiveData.exe -output frame.csv

指定雷达 IP 并等待最多 60 秒：
  ./receiveData.exe -source 192.168.1.100 -timeout 60s -output frame.csv

查看全部参数：
  ./receiveData.exe -h

以上 ./receiveData.exe 命令也可在 PowerShell 使用。
路径包含空格时请用双引号包围路径；输出目录须提前存在。
已有同名文件不会被覆盖，请改名或使用默认时间戳文件名。

4. 命令行参数
  -listen   本地 IPv4 UDP 监听地址，默认 0.0.0.0:1995。
            0.0.0.0 表示监听所有本地 IPv4 网卡，适合接收广播。
  -source   可选的雷达 IPv4 地址，默认不限定 IP。
            无论是否设置此项，接收器都会锁定首个合法 offset=0 包的来源
            IP 和 UDP 源端口，本次运行后续仅接收同一来源。
  -timeout  采集等待时长，默认 30s；支持如 60s、2m；0 表示无限等待。
            不允许负数。超时针对收帧阶段，不限制后续 CSV 写入时间。
  -output   CSV 输出路径，默认使用当前工作目录内的时间戳文件名。
  -h        显示帮助并退出。

5. 数据协议及完整帧判定
协议依据：exampleCode/merger.go；实现位于 lib/radar。
一个应用层 UDP 数据包为 8196 字节，不含 UDP/IP 协议头：
  字节 0..3    uint32 小端偏移量，表示载荷在原始帧中的字节位置。
  字节 4..8195 8192 字节原始采样载荷。

偏移量按 0、8192、16384、……、8380416 依次递增。
连续 1024 个包的载荷拼接为 8388608 字节（8 MiB）原始帧。
包长错误、偏移越界、偏移未按 8192 对齐或顺序不连续时，丢弃当前组帧进度。
新的 offset=0 包立即从帧头重新组装；起始零偏移包重复到达也会重新开始。
协议没有帧编号，不进行乱序重排或跨帧补包。
SYNC 校验失败后继续等待下一帧，不导出该无效帧。

原始帧按采样时刻依次存放 ch0..ch7，每通道每采样占 2 字节，小端编码。
导出的 ADC 值 = 原始 uint16 >> 2，范围 0..16383，不做符号扩展。
bit 1 用于通道 6、7 的 SYNC 校验；bit 0 的含义参考代码未定义，导出时丢弃。

每周期 2125 个采样点，对每个完整周期的通道 6、7 校验：
  周期内索引 2..1751：bit 1 必须为 1。
  周期内索引 1755..2123：bit 1 必须为 0。
  索引 0、1、1752、1753、1754、2124：不检查，沿用原代码边界容差。
最后不足一个周期的真实采样保留导出，不进行上述周期校验。

6. CSV 输出格式
表头：
period_index,sample_in_period,ch6,ch7

每行包含周期编号、周期内索引及同一采样时刻的 ch6、ch7 两个 ADC 值。
按采集顺序排列，两种索引均从 0 开始。
  period_index     周期编号，采样序号 / 2125 向下取整，范围 0..246。
  sample_in_period 周期内索引，采样序号 % 2125，完整周期范围 0..2124。
  ch6              通道 6 的解码后 ADC 值。
  ch7              通道 7 的解码后 ADC 值。
不包含 ch0..ch5 或全帧 sample_index 列。
第一行数据的索引为 0,0；最后一行数据的索引为 246,1537。

CSV 有 524288 行数据，另有 1 行表头，共 524289 行。
其中包含 246 个完整周期，以及最后一个周期的 1538 个真实采样点。
不会导出参考代码 Parsed 数组末尾的补零内容。
CSV 不含原始包偏移量、SYNC 位或接收时间列。

7. 从源码运行、构建和验证
在仓库根目录执行：
  go run ./toolbox/receiveData
  go build -o toolbox/receiveData/receiveData.exe ./toolbox/receiveData
  go test ./...
  go vet ./...

文件职责：
  toolbox/receiveData/main.go  参数、监听初始化、取消/超时、保存与退出。
  lib/radar/receive.go         UDP 读取、来源过滤与锁定、接收循环。
  lib/radar/frame.go           协议常量、包检查、顺序组帧、SYNC 校验、采样解码。
  lib/radar/csv.go             CSV 写入、禁止覆盖、写入失败时清理不完整文件。
  test/radar_test.go           模拟数据及本地 UDP 集成测试。

8. 常见问题
一直等待或超时：检查雷达是否发送、网卡所在网段、防火墙、端口及 -source IP。
报 listen 错误：检查端口占用、本机 IP 是否有效。
报 bad sync 或 bad offset：说明收到的数据未满足参考协议；检查设备输出、
丢包及网络状况。工具会持续尝试，直到成功、超时或用户取消。
报 save CSV 错误：检查文件是否已存在、目录是否存在、权限及磁盘空间。
无法扩大 UDP 缓冲区：工具输出 Warning 后继续运行，但高速输入可能增加丢包。
退出码：正常保存或查看帮助为 0；参数、收帧、超时、取消或保存失败为 1。
